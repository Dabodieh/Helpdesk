# Phase 2 threat model: ticketing

Owner: QA/Security. Scope: the ticket endpoints of `docs/api/PHASE2_API.md`, the `ticketing` schema and `ITicketIngress`. Rules: `PERMISSIONS.md`, `TICKETING.md`, ADR-005/009/012. Severity: any cross-department leak is Critical.
Tests live in `tests/Helpdesk.Host.Tests/Ticketing/`: `TicketIsolationMatrixTests` (M), `TicketIsolationLeakageTests` (L); older proofs are `TicketCreationTests`, `TicketChangeTests`, `TicketMessageTests`, `TicketQueueTests`, `TicketIngressAndScopeTests` (existing), `Organisation/AuthorizationDecisionTests` and `Helpdesk.ArchitectureTests` (arch).

## Assets
| Asset | Why it matters |
|---|---|
| Ticket content (subject, requester identity, message bodies) | Confidential; department isolation is the core product promise |
| Internal notes | Agent-only; leaking them to a requester or other department is worse than leaking public text |
| Requester directory (name, email) | Personal data; per department by design |
| Ticket state (status, assignee, team, priority) and `version` | Integrity; wrong assignee or silently lost edits cause real work errors |
| Audit stream (`audit.audit_events`, category `ticketing`) | Authoritative history; must be append-only, complete and free of message bodies |
| References and numbering | Guessable by design (`KEY-n`); must never be a way in |

## Trust boundaries
1. Browser/API client to Host: cookie session, CSRF header on unsafe methods, JSON bodies and query strings are fully untrusted.
2. Host to Ticketing module: `IAuthorizer` and the department scope (`IDepartmentScope`, global query filter, fail closed) decide visibility; the department always comes from the persisted ticket, never from the request.
3. Ticketing to Organisation/Identity/Audit: only Contracts (arch tests); assignee/team validity is checked in the service and again by composite FKs.
4. Application to PostgreSQL: parameterised EF/Npgsql only; CHECKs and composite FKs are the last line. The application role can still UPDATE/DELETE (separate DB roles are open, see residual risks).
5. Phase 3 mail ingestion (`ITicketIngress`): in-process only, department from the mailbox, never exposed over HTTP.

## Abuse cases, mitigations, proofs
| # | Abuse case | Mitigation | Proof |
|---|---|---|---|
| T1 | Outsider (anonymous, no membership, platform admin without membership, member or admin of another department) reads or changes a ticket by id, by reference, in any case form | Resolve through scoped set (404), then permission on persisted department (403); platform flag gives no content access | M `Endpoint_by_persona_returns_the_contract_status_and_leaks_nothing` (19 endpoints x 9 personas, exact status, DB snapshot unchanged on every denied call, successes really mutate); M `Every_ticket_route_resolves_all_reference_forms...`; existing `Ticket_routes_never_reveal...`, `AuthorizationDecisionTests` |
| T1b | Existence oracle: tell "exists in B" from "does not exist" | 404 byte-identical (status, headers, problem body minus traceId/instance) to the 404 for a random GUID, a guessed reference with the real key and a random-key reference; no Location/ETag/Content-Location on 401/404; body never echoes id, reference, key, department name, subject | M matrix (per case); M `Foreign_filters_are_indistinguishable_from_random_filters...`; L `Malformed_json_answers_the_same...`; L `Requesters_are_per_department...`; L `Invalid_teams_and_assignees...` (foreign team/user ids give the same 409 as random ones) |
| T1c | Fuzzy reference resolution (zero padding, whitespace, suffix, other key) | Exact, anchored reference match only; upper-cased once | L `A_reference_is_canonical_immutable_and_never_resolved_fuzzily` |
| T2 | Foreign rows through lists, queues, counts, filters, sorts, cursors, `departmentId`/`teamId`/`assigneeUserId` of another department | Scope applied in the query (global filter); filters only narrow; inaccessible ids give an empty page | M `Lists_and_counts_contain_only_the_personas_own_departments` (exact `all` count equals the department's Open tickets); L `No_combination_of_queue_sort_status_and_foreign_filters...` (4 queues x 5 sorts x 6 filters, paged to the end); existing `Filters_only_narrow...`, `Queue_counts...` |
| T3 | Cursor replay or forgery to step outside scope; injection through cursor/search | Cursors are unsigned but only carry sort key + id of a row the caller already saw; every page is still the scoped query; strict parsing | L `Cursors_replayed_by_other_callers_or_forged...` (12 forgeries x 5 sorts, never a foreign row, never 5xx), L `Message_and_activity_cursors_cannot_cross_tickets_or_departments`, L `Search_input_cannot_widen_the_scope...` (`% _ \` and injection strings are literal; foreign reference/subject finds nothing; 100/101 chars) |
| T4 | Internal note read or written without permission; note leaks via lists, search, activity, audit, logs; kind flipped | `tickets.note` / `tickets.notes.read` checked server side; notes excluded in the query; search covers reference+subject only; audit stores no bodies; no message-by-id or message-update route; DB CHECK ties Internal to Agent/System and delivery `None` | L `Message_bodies_appear_only_in_the_messages_endpoint_and_never_in_audit_activity_search_lists_or_logs` (8 personas x 7 reads, audit rows, captured Serilog output); L `Notes_need_tickets_note_...` and `Without_notes_read_...` (restricted authorizers, paging with filtered rows, fail closed without `tickets.read`); L `A_messages_kind_cannot_be_changed_and_no_route_addresses_a_single_message` (5 methods x 5 route shapes x 2 personas); existing `Internal_notes_are_excluded...`, `Message_check_constraints...`, `Message_bodies_never_reach_the_audit_stream` |
| T5 | Requester leakage across departments (lookup, counts, `requesterId`, same email in two departments) | Requesters are department rows (unique per department+email); composite FK; lookup scoped by route department | L `Requesters_are_per_department...`; existing `Requester_is_upserted...`, `Requester_lookup_is_department_scoped...` |
| T6 | Assignee or team outside the department (create or assign), self-assign abuse | Service validation (`invalid_state`) plus composite FKs; assign.self limited to taking/releasing for oneself with the team unchanged; one indistinguishable message for every refused assignee | L `Invalid_teams_and_assignees_...` (7 assignee and 3 team cases x create/assign/admin, inactive user and team included, DB unchanged); L `Assign_self_covers_...`; existing `Assignment_to_a_team_or_user_outside...`, `The_database_composite_foreign_keys...` |
| T7 | Stored XSS / HTML injection through subject, description, names, messages | API is JSON only, `application/json; charset=utf-8`, no HTML rendering path, bodies plain text; React escapes. HTML sanitising is a Phase 3 concern (mail) | L `Markup_is_stored_and_returned_verbatim_as_json_text...` (9 payloads x 6 responses). Gap: no `X-Content-Type-Options: nosniff` or any other security header on API responses (L `KNOWN_GAP_...`) |
| T8 | Mass assignment (status, reference, number, id, department, createdBy, timestamps, authorType, deliveryState, kind, source, ids of foreign tickets/messages) | Request DTOs carry only the permitted fields; unknown JSON members are ignored | L `Extra_json_fields_never_set_server_owned_values...` (create, patch, assignment, message), L `Department_ids_in_route_body_query_or_headers_never_override...` |
| T9 | CSRF on unsafe ticket routes | Antiforgery token bound to the user, validated before authentication (400 `csrf_invalid`) | L `Every_unsafe_ticket_route_refuses_...` (4 routes x 6 token variants, plus a control that the same request succeeds with a valid token); arch `Unsafe_methods_are_never_anonymous` |
| T10 | Rewriting a reference | Not in any DTO; DB trigger/CHECK; department key immutable | L `A_reference_is_canonical_immutable...`; existing `Renaming_the_department_never_changes_references` |
| T11 | Lost updates and races: same-version writers, message while editing, assignment vs membership removal, same-email requester creation | `FOR UPDATE` + version compare in one transaction, 409 `version_conflict`; composite FK `ON DELETE SET NULL (assignee_user_id)`; FK violation mapped to 409 `invalid_state`; requester upsert `ON CONFLICT DO NOTHING` | L `Of_many_writers_with_the_same_version...` (9 writers: exactly one 200), L `Concurrent_patch_assignment_and_message...`, L `A_message_posted_while_another_agent_is_editing...`, L `Assignment_racing_a_membership_removal...` (12 rounds: never an assignee outside the department, never 5xx), L `Parallel_creations_for_one_new_requester_address...`; existing `A_stale_version_is_a_version_conflict...` |
| T12 | Stale access after removal, demotion or deactivation | Authorizer and scope are loaded per request from the database | L `Access_follows_membership_role_and_account_changes_on_the_next_request`; existing `Removing_a_membership_takes_effect...` |
| T13 | Hostile input causing errors | Validation with 400 and per-field errors | L `Hostile_input_is_rejected_or_stored_never_a_server_error`, L `Malformed_json_...`. U+0000 is rejected with 400 (L `NUL_characters_in_text_fields_must_be_a_400_not_a_server_error`; found by QA, fixed) |
| T14 | Message bodies or tokens in logs | Serilog request logging records path and status only; bodies never passed to logger | L `Message_bodies_appear_only_in_the_messages_endpoint...` (log sink capture at the host's configured level) |
| T15 | Ingestion bypasses isolation | `ITicketIngress` takes the department explicitly and re-checks ticket and requester against it | existing `Ingress_is_bound_to_the_department...`, `A_context_whose_scope_was_never_loaded_sees_nothing`, arch `IgnoreDepartmentScope_is_called_only_from_the_reviewed_call_sites` |

## Residual risks and known limitations
| ID | Item | Severity | Note |
|---|---|---|---|
| Q-1 (FIXED in Phase 2) | U+0000 in any text field, or in `q`, returns 500 | Medium (robustness, no leak, no stack trace in the body) | Reproduction: `POST /api/departments/{d}/tickets` with `subject` containing `\u0000`; also messages, PATCH subject, `GET /api/tickets?q=%00`, requester lookup. Reject U+0000 in `TicketValidation` and the `q` parameters. Test: `KNOWN_DEFECT_NUL_...` (fails until fixed) |
| Q-2 (FIXED for API responses) | No security headers at all on API responses (`nosniff`, HSTS, CSP, `Referrer-Policy`, `Cache-Control: no-store` for ticket data) | Low to Medium | SECURITY.md lists security headers; nothing implements them and BACKLOG has no entry. Ticket JSON contains user markup verbatim, so `nosniff` and `no-store` are the minimum. Test: `KNOWN_GAP_...` (fails until fixed) |
| Q-3 | Messages are append-only only by convention: the application DB role can UPDATE/DELETE `ticketing.messages` (no trigger like the audit table); an Internal note can be turned Public by SQL | Medium (needs DB access) | Same family as the open "separate DB roles" item; add an update/delete-rejecting trigger when roles land |
| Q-4 | Removing a membership silently unassigns its tickets without a ticket event | Low | Documented in TICKETING.md invariant 4 |
| Q-5 | Posting a message changes the ticket `version`, so an agent editing a stale view gets 409 after any colleague replies | Low (UX) | Intended: messages are not version-guarded; tested; document in PHASE2_API |
| Q-6 | `assign.self` lets an agent take a ticket assigned to another agent (no ownership check) | Low | Matches the contract and is audited; confirm it is intended |
| Q-7 | Free-text fields accept control characters and markup: subject allows CR/LF, requester email allows `<`, `>` (no whitespace, one `@`) | Low now, High when Phase 3 builds mail headers/HTML from them | Phase 3 must strip CR/LF from subjects and encode every value in mail headers and templates; requester email needs RFC-grade validation before use in `To:` |
| Q-8 | Cursors are unsigned base64 | Low | No leak possible (scope applies to every page); revisit if a cursor ever embeds more than sort key + id |
| Q-9 | Timing differences (found vs not found) are not measured | Low | Both paths run the same scoped lookup before any other work; no timing test (not reliable in CI) |
| Q-10 | Rate limiting, separate DB roles, persisted Data Protection keys | Existing | See SECURITY.md and BACKLOG |
| Q-11 | No attachment, HTML mail or outbound mail yet | n/a | Re-run this model in Phase 3 (mail ingestion, sender spoofing, sanitising, attachments) |

## How to re-run
`dotnet test tests/Helpdesk.Host.Tests --filter "FullyQualifiedName~TicketIsolation"` (about 15 s with PostgreSQL up). All cases pass; Q-1 (NUL characters) and Q-2 (nosniff, no-store, CSP, Referrer-Policy on API responses; HSTS outside Development/Testing) were fixed in Phase 2. The SPA's own headers are the reverse proxy's job.
