## Completed sections

- Application shell and navigation: Graphite global rail, contextual queue navigation, top bar, real search, notifications, creation and account actions. Manrope is bundled with its licence. Explicit light/dark preference uses guarded existing preference storage; dark is the default.
- Shell verification: App tests 4/4, theme preference tests 2/2. Local real-API browser screenshots checked in dark and light at 1366×768, without horizontal overflow.

Database, permission boundaries, ticket workflows, notification delivery, SLA calculations and email behavior are unchanged. The only API addition is the authenticated attachment UI capability described below. Browser plugin bootstrap is broken (missing service module); local installed Playwright/Edge is used for visual evidence instead. Screenshots are local ignored artifacts under `src/web/TestResults/`.
- Administration and Department Overview: full-height grouped navigation, searchable/status-filtered department table, grouped setup rows and contextual details. Existing permission-gated queries and edit flows retained. Targeted administration tests: 14/14 passed (updated selectors for grouped setup lists and field roles). Real local API views checked in both themes at 1366×768 and 1440×900; no viewport overflow.
- Mailbox Management: compact operational summary, combined sender/health/sync table, subscription detail disclosure, create/edit drawers, and prioritised mail attention. Admin sender controls, warnings, retries and acknowledgement settings remain connected to existing APIs. Targeted mailbox tests: 5/5 passed, including permissions, creation and uncertain-send handling. Both themes checked at both target sizes, including the edit drawer.
- Agent Workspace: resizable compact queue with visible priority/SLA/response state, collapsible advanced filters, Graphite conversation and composer, and a restrained properties rail. Sender addresses removed from ticket properties and new-ticket choices; mailbox administration actions and unavailable-email warnings retained. Targeted tests: workspace/queue/properties 38, sender/mail rendering 6, split sizing 1 (45 passed). TypeScript compile passed. Both themes and target sizes checked; note mode, properties toggle and a real-API mail-failure filter exercised.

- Remaining pages: shared Graphite form, table, dialog and editor styles applied across existing configuration pages, dashboard, profile, responses, requester history, teams and portal. Portal navigation includes the theme switch. Nested configuration tabs retain horizontal navigation; team details use the shared page header. Dashboard mailbox health uses the display name instead of the sender address. System status offers a real readiness refresh.
- Attachment visibility: requester form/reply upload controls are hidden while attachments are disabled, pending or unavailable. A new read-only `GET /api/portal/capabilities` reports only `attachmentsEnabled` from `IAttachmentStore.Enabled`; upload/download authorization, scanning and storage are unchanged. Existing attachment downloads remain governed by server-returned `downloadable`. No schema/migration changes. API contract updated in `docs/api/PHASE6_API.md`.
- Remaining verification: attachment visibility/reply tests 7, dashboard tests 3, help-topic/form routing tests 3, and affected sign-in/status/team tests 3 passed (16 frontend tests). Capability integration tests 2/2 passed, including anonymous rejection and both configuration values, against a disposable database on the configured local PostgreSQL port. Initial default-port failure was an environment mismatch (Windows PostgreSQL on 5432; project container on 5433). TypeScript compilation and frontend build passed; Vite retains a non-blocking large-chunk warning. No full test suite or production deployment.
- Real-API visual checks: dashboard, profile, responses, ticket setup, SLA settings, system status, portal home, knowledge, request form, requester conversation and team details captured in both themes at 1366×768 and 1440×900; requester history checked in both themes at 1366×768. Existing demo records were used, with no ticket/configuration writes. Upload controls were also checked against the new capability endpoint with the local attachment setting disabled. A separate temporary local host had migrations and jobs disabled. Main flows remained within the viewport; long pages and sidebar navigation scroll independently.
- Authentication metadata was checked against the official ASP.NET Core 10 [Minimal API security documentation](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/minimal-apis/security?view=aspnetcore-10.0). The existing `RequireAuthenticatedOnly` endpoint pattern was reused; no authorization policy was changed.
